## 2. Entrypoints & Startup Commands

### 2a. Fabric Test Network

```bash
cd test-network

# Start 2-org network + channel + deploy basic chaincode
./network.sh up createChannel -c mychannel -ca
./network.sh deployCC -ccn basic -ccp ../asset-transfer-basic/chaincode-go -ccl go

# Tear down
./network.sh down
```

Key files:
- `test-network/network.sh` — main orchestration script (Docker Compose)
- `test-network/scripts/deployCC.sh` — chaincode lifecycle automation
- `test-network/scripts/envVar.sh` — peer environment helpers
- `test-network/configtx/` — channel configuration YAML

### 2b. Dashboard Backend

```bash
cd dashboard/backend
npm install
node server.js
# Listening on http://localhost:4000
```

Requires: Fabric test network running, `connection-org1.yaml` correct, wallet populated.

### 2c. RBCM Reputation Engine

```bash
cd rbcm-engine
pip install -r requirements.txt
python reputation_engine.py
# Listening on http://0.0.0.0:5000
```

**Or via Docker:**

```bash
docker build -t rbcm-engine rbcm-engine/
docker run -p 5000:5000 rbcm-engine
```

### 2d. Off-Chain Data Listener (Go)

```bash
cd off_chain_data/application-go
# Set Fabric env vars, then:
go run .
```

## 5. Top 10 Technical Risks & Refactor Priorities

### 🔴 Critical

**R1 — Private key material committed to source control (FIXED)**  
`dashboard/backend/wallet/appUser.id` previously contained a live X.509 private key.  
*Fix:* File removed from tracking; `wallet/` added to `.gitignore`. Regenerate wallet identities locally (see `dashboard/README.md`).

**R2 — Hardcoded absolute paths in `server.js`**  
`certPath` and `keyStorePath` are hardcoded to `~/new/fabric-samples/…`. These will fail on any machine other than the original developer's.  
*Recommendation:* Replace with environment variables (`CERT_PATH`, `KEY_STORE_PATH`) or a config file.

### 🟠 High

**R3 — In-memory score storage in `reputation_engine.py`**  
All node scores are stored in a plain Python dict (`scores = {}`). A restart of the engine resets all scores to zero.  
*Recommendation:* Back the store with Redis (`redis-py`) or a lightweight SQLite DB.

**R4 — Reputation scores not integrated with Fabric**  
`/api/stats` in `server.js` assigns random scores (`95 + Math.random() * 3`) rather than calling the reputation engine. The two services are currently disconnected.  
*Recommendation:* Wire `/api/stats` to `POST http://rbcm-engine:5000/update_score` for actual per-peer scoring.

**R5 — No authentication on dashboard or engine APIs**  
Both services (`port 4000` and `port 5000`) accept unauthenticated requests from any origin (`cors()` with no restriction).  
*Recommendation:* Add API key middleware or JWT verification; restrict CORS to the dashboard's origin.

**R6 — `express` v5 (unstable) declared in `package.json`**  
`"express": "^5.2.1"` pins to the Express 5 beta/release candidate line. Express 5 was not production-stable at the time of writing.  
*Recommendation:* Lock to `"express": "^4.21.2"` for production stability.

### 🟡 Medium

**R7 — Shell injection risk in `exec('docker ps … | grep …')`**  
`server.js` calls `child_process.exec` with a shell command that incorporates no untrusted user input, but the pattern is fragile: if `docker` is not in `PATH` or the format changes, the server silently returns an empty list.  
*Recommendation:* Use the `dockerode` library (already a declared dependency) to list containers programmatically.

**R8 — `venv/` directory was tracked in git**  
The entire Python virtual environment (~hundreds of files) was committed to the repo, bloating history.  
*Fix:* `venv/` now added to `.gitignore` and removed from tracking; use `pip install -r requirements.txt` instead.

**R9 — No `requirements.txt` for the reputation engine**  
Dependencies were installed ad-hoc via Dockerfile. Running locally required guessing the packages.  
*Fix:* `rbcm-engine/requirements.txt` added.

**R10 — No error handling for missing wallet identity in dashboard**  
`setupWallet()` silently returns `undefined` on error. Subsequent `gateway.connect()` calls will throw unhandled rejections.  
*Recommendation:* Propagate the error with `throw error` and add Express error middleware to return proper HTTP 500 responses.

## 6. Recommended Next Steps

1. **Inject env vars** for cert/key paths in `dashboard/backend/server.js` (fixes R2).
2. **Add Redis** to the `rbcm-engine` for persistent scores (fixes R3).
3. **Connect dashboard → engine** so `/api/stats` scores are real (fixes R4).
4. **Add auth middleware** to both services (fixes R5).
5. **Pin Express to v4** until v5 is production-stable (fixes R6).
6. **Switch from `exec` to `dockerode`** for container listing (fixes R7).
